## 1. 整体架构

```
前端 React SPA（单页，无 URL 路由）
   │
   ├── 转发代理层  /api/fetch?u=  /api/stream?u=  /api/img?u=   ← 外部源统一走 ?u=
   │
   ├── 内置列表层  /api/lists → POST /api/dev 换 key → /api/x/k/{key}/{id}/player_api.php
   │
   ├── 元数据层    /api/discover /similar /trailer /skip /saga /ratings /pessoa /art /epg /airing /apoiadores
   │
   ├── 字幕层      /api/legendas  /api/legenda                  ← 新版新增
   │
   └── 账户设备层  /api/conta/*  /api/conta/tv  /api/conta/tv/controle
```

**统一约定**

- Base URL：`https://hypetvbr.com/`（前端用 `<meta name="hypetv-url">` 确定 API 基址）
- 响应编码：`application/json;charset=utf-8`（代理类透传目标 Content-Type）
- CORS：`access-control-allow-origin: *`，暴露 `content-length, content-range, accept-ranges, content-type, etag`
- 错误格式：`{ "error": "葡语错误信息" }`
- 缓存：内置列表接口 `cache-control: no-store`；元数据前端用 Map 记忆化

## 2. 开发者码鉴权与内置列表（核心变化）

### 2.1 `POST /api/dev` —— 开发者码换 key（实测）

**请求**
```bash
curl -sS -X POST 'https://hypetvbr.com/api/dev' \
  -H 'content-type: application/json' \
  -d '{"code":"123"}'
```

**实测响应（HTTP 200）**
```json
{
  "key": "cfc467d74225f369b541d032",
  "lists": [
    {"id": "1", "name": "Minha lista"},
    {"id": "2", "name": "Lista-2"}
  ]
}
```

- 错误码：无效码 → **403** `{"error":"Código inválido"}`
- 前端拿到 `key` + `lists` 后，把每个列表组装成：
  ```
  id: devlist-{id}
  name: [dev] {name}
  type: xtream
  server: {base}/api/x/k/{key}/{id}
  username: "-"    password: "-"
  ```
- 前端逻辑（`api/lists` → `server-{id}` → `api/x/{id}`，`api/dev` → `devlist-{id}` → `api/x/k/{key}/{id}`）在 JS 中完整保留——**功能没删，只是默认不暴露**。
- 开发者码由站主发放，可能随时变更；`key` 与码绑定。

### 2.2 `GET /api/lists` —— 内置列表清单（实测返回空）

```bash
curl -sS 'https://hypetvbr.com/api/lists'
# → []
```

带浏览器头、`?tv=1`/`?store=1`/`?dev=1` 均返回 `[]`。普通访问拿不到列表，必须走 2.1 的开发者码路径。

### 2.3 内置列表 Xtream 接口（实测）

**Base**：`https://hypetvbr.com/api/x/k/{key}/{id}/player_api.php?username=-&password=-`

**实测数据条数**

| action | 列表 1（Minha lista） | 列表 2（Lista-2） |
|---|---|---|
| `get_vod_streams`（电影） | **43970**（9.6MB） | **27816**（6.6MB） |

**请求示例**

**电影条目字段（实测）**

## 3. 转发代理接口

三个端点与旧版行为完全一致，**只把域名换成 hypetvbr.com**。

### 3.1 `GET /api/fetch?u=` —— 抓列表/元数据原文

```bash
curl -sS 'https://hypetvbr.com/api/fetch?u=https%3A%2F%2Fiptv-org.github.io%2Fiptv%2Fcountries%2Fbr.m3u&ua=&ref='
```
实测：`audio/x-mpegurl`，返回完整 M3U 原文。新站"Testar com canais abertos"按钮就是请求这条（401 个频道）。

### 3.2 `GET /api/stream?u=` —— 拉流代理

```bash
curl -sS -H 'Range: bytes=0-50' 'https://hypetvbr.com/api/stream?u=<编码后的流地址>'
```
实测：`content-type: application/vnd.apple.mpegurl`；**Range 请求仍返回 200 全量，未实现 206 分段**（旧版同）。

### 3.3 `GET /api/img?u=` —— 图片代理

```bash
curl -sS 'https://hypetvbr.com/api/img?u=https%3A%2F%2Fimage.tmdb.org%2Ft%2Fp%2Fw342%2Fxxx.jpg'
```
实测：`image/jpeg`，200。

### 3.4 代理 URL 构造（前端 `Ei()`）

```js
function Ei(kind, url, headers, live=false) {
  if (Ci(url)) return url;              // 已是本站 api/ 地址 → 原样返回
  let i = new URL(`api/${kind}`, base);
  i.searchParams.set('u', url);         // 目标地址 → ?u=
  headers?.ua && i.searchParams.set('ua', headers.ua);
  headers?.ref && i.searchParams.set('ref', headers.ref);
  live && i.searchParams.set('live','1');
  return i.href;
}
```

## 7. 播放地址生成（mp4 为主）

### 7.1 列表里没有播放地址

实测 `get_vod_streams` 字段全集：`added, category_id, container_extension, name, rating, stream_icon, stream_id, year`——**唯一含 http 的字段是 `stream_icon`（海报）**。播放地址由前端用零件拼出。

### 7.2 Xtream 地址模板（前端 `url()` / `section()`）

| 类型 | 模板 | 实测 |
|---|---|---|
| 电影 mp4 | `{base}/movie/-/-/{stream_id}.{container_extension}` | `/api/x/k/{key}/1/movie/-/-/4564035.mp4` |
| 剧集 mp4 | `{base}/series/-/-/{episode_id}.{ext}` | `/api/x/k/{key}/1/series/-/-/4766400.mp4` |
| 直播 | `{base}/live/-/-/{stream_id}.m3u8`（`.ts` 作 alt） | 可忽略 |

扩展名兜底 `wa(e,t)=/^[a-z0-9]{2,5}$/i.test(e)?e:t`——非法则默认 `mp4`。

### 7.3 新站 mp4 行为变化：302 跳转到 CDN（实测）

```bash
curl -sS -D - -o /dev/null 'https://hypetvbr.com/api/x/k/{key}/1/movie/-/-/4564035.mp4'
# HTTP/2 302
# location: https://vod.zonaliveboxcdndiexsystem.fun/Filmes/394997.mp4
```
- 电影：302 → 真实 CDN mp4（实测 2.9GB，`video/mp4`）
- 剧集：`HTTP 206`，`video/mp4`，最终落到 `vod.zonaliveboxcdndiexsystem.fun/Series/283329.mp4`
- **旧站是直接 206，新站电影先 302 再跳**——做测速/下载时要跟随跳转（`curl -L`）

### 7.4 播放前的前端加工

1. `zl()` 引擎判断：`.m3u8`→hls、`.ts`→mpegts、`.mp4/.avi…`→native
2. `Vl()` 候选展开：`[url, ...alt]` × 引擎 × 直连/代理，最多 6 个
3. `Ei()` 代理封装：仅非本站地址才套 `?u=`
4. `Hl()` 逐个尝试，成功即播；新站额外挂字幕与缩略图

## 8. tmdb_id 映射（正向 / 反向）

### 8.1 正向：stream_id → tmdb_id

| 类型 | tmdb_id 位置 | 实测 |
|---|---|---|
| 电影 | `get_vod_info&vod_id=X` → `info.tmdb_id` | `vod_id=4564035` → `1228710` |
| 剧集 | `get_series_info&series_id=X` → `episodes[*].info.tmdb_id` | `series_id=17574` → `96885` |

剧集的 tmdb_id **藏在分集 info 里**，顶层 `info` 没有；前端 `Oa()` 只读顶层，所以没利用这个字段。

### 8.2 反向：tmdb_id → stream_id

**没有反向 API**（三种尝试均失败：`get_vod_info?vod_id={tmdb}` 空、`get_vod_streams?tmdb_id=` 被忽略、`/api/meta?tmdb=` 等全 404）。两条路径：

- **A 全量倒排索引**：遍历全部详情建 `{tmdb_id:[stream_id...]}`，约 5.4 万次请求，最准；覆盖率有缺口（抽样 15 部电影，10 部成人片 `tmdb_id=0`）
- **B 片名桥接 + 详情验证**（推荐）：`tmdb_id → TMDB 查片名/年份 → 本地列表 `Xo()` 规范化 + 年份容差≤1 筛候选 → 逐个调详情比对 tmdb_id 相等`

**一名多 stream**：规范化后 4267 组重复、涉及 9159 条；如 tmdb=297762（神奇女侠）对应 4 个 stream_id（画质/配音版）。反向输出天然是候选列表，需再加择优规则。

## 11. 缓存与本地存储（前端侧）

- 元数据 Promise 记忆化（similar/trailer/saga/skip/ratings/pessoa/legendas），失败即 `delete` 便于重试

## 12. 对 IPTV 清洗项目的参考要点

1. **地址是"零件 + 模板"**：`stream_id + container_extension` → `{base}/{kind}/-/-/{id}.{ext}`，别指望接口直接给 URL
2. **新站 mp4 先 302 再跳 CDN**：测速必须 `curl -L` 跟随，否则拿到的是 302 空响应
3. **"HTTP 200 但内容是错误页"识别**：旧站 `ji()` 会嗅探前 4000 字符匹配 `INVALID_CREDENTIALS/EXPIRED/BANNED/MAX_CONNECTIONS` 转错误
4. **片名↔元数据模糊关联**：无外键，靠 `Xo()` 规范化 + 年份容差≤1；`tmdb` 只用于元数据增强
5. **剧集 tmdb_id 在分集里**：提取时要遍历 `episodes[*].info`，别只看顶层
6. **内置列表数据**：新站需开发者码换取，旧快照已打包保存于 `/workspace/媒体列表快照-20251124.zip`
